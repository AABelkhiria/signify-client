## What this is

Roadmap 9.1 audits the whole upstream unit suite against this port: **every case must be answered
by Rust evidence or by a documented `N/A`**. Two files hold the comparison.

`v1.json` is the **inventory** — generated by reading the reference's own syntax tree. For each
case it records the file, the `describe` chain, the title, how many assertions it makes, which
assertion helpers it uses, and which upstream modules its file imports.

`ledger.json` is the **answer** — authored, not generated, because "this Rust test answers that
upstream case" is a judgement a generator cannot make. Each entry names the roadmap item, the
evidence, and a note.

`crates/signify-client/tests/upstream_unit_audit.rs` is what keeps the judgement honest. It
requires the two to agree exactly, and — the part that matters — it requires **every path the
ledger names to exist on disk**. A ledger entry pointing at a test that was renamed or a fixture
that was never written fails there rather than reading as coverage. It also caught two numbers in
the findings below that had been taken on trust rather than counted.

## The result

| | |
|---|---:|
| upstream cases | 139 |
| answered by Rust evidence | 137 |
| documented `N/A` | 2 |
| upstream assertions excused | **0** |

The two exemptions are the same thing: `Aiding › Typings test › CreateIdentiferArgs` and
`RotateIdentifierArgs`, which make **zero assertions**. They are TypeScript type tests — they
declare a literal and check it is assignable. Rust has no equivalent test to write, because the
equivalent claim is that the crate compiles. The audit test verifies these are the only
zero-assertion cases in the suite, so an exemption cannot be claimed for a case that actually
checks something.

Counting cases alone would let one heavy case hide behind a light one, so the audit is also checked
by weight: the assertions it excuses must total zero, and any case making forty or more assertions
must name more than one piece of evidence.

## What the audit found

Behaviourally, nothing is missing. Structurally, two things are — and they are the same thing seen
twice.

**Eleven of the forty test files import from `src/index.ts`**, the package entry point, rather than
from the module under test: `Signer` and `Matter` in one file, `Serder` and `versify` in another.
Every symbol they reach is individually ported and `VERIFIED`. What is not is the entry point
itself, whose `PORTING.md` §4.1 row is `TODO`, because the curated re-export surface belongs to
Roadmap 9.5. So a quarter of the suite imports through a surface this port has not settled.

**Ten of them reach `src/keri/app/clienting.ts`**, whose row is `IN_PROGRESS` for the same reason —
every capability behind it is `VERIFIED`, and only the shape of the accessors is open.

Both are Roadmap 9.5's to close, and Phase 9's exit gate requires it. Neither leaves a unit case
unanswered.

## Determinism

The inventory is a pure function of the pinned checkout: no clock, no randomness, no network. It
fails loudly rather than silently if the reference grows a case with a computed title, two cases
with the same key, or a skipped case — any of which would make the ledger unkeyable or the count
wrong.

Rust tests consume both checked-in files and require neither Node nor network access.
