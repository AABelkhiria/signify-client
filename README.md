# signify-client

A Rust SDK for signing at the edge with KERI, ACDC and KERIA: the Signify client and the crates it
is built on. The behavior and wire bytes match
[signify-ts](https://github.com/WebOfTrust/signify-ts), checked against fixtures it generates.

## Crates

| Crate | Purpose |
|---|---|
| [`signify-client`](crates/signify-client) | The SDK's entry point: client lifecycle, every KERIA endpoint family, multisig and IPEX workflows. Re-exports everything below. |
| [`signify-http`](crates/signify-http) | Transport abstraction, signed requests and responses, retries, and the production HTTP transport behind the `http-client` feature. |
| [`signify-keys`](crates/signify-keys) | Key management: keepers, identifier habitats, the client's own controller, and ACDC signing. |

An application depends on `signify-client` alone. The protocol crates it builds on, `keri-cesr`,
`keri-protocol`, `keri-acdc`, `keri-http-auth` and `keria-types`, are reachable from its root.

`crates/signify-keria-systest` is not published. It holds opt-in system tests that record what a
live KERIA deployment answers, so the hermetic tests in `signify-client` can assert against it.

## Use

```bash
cargo add signify-client --features http-client
```

See the [`signify-client` README](crates/signify-client/README.md) for a usage sketch.

## Prerequisites

- Rust 1.97 or newer (`rustup` installs the toolchain pinned in `rust-toolchain.toml`).
- Nightly Rust and `cargo-fuzz`, only for fuzzing.
- Node 22 or newer, `uv` and `libsodium`, only to regenerate the fixtures.

## Build and test

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features
cargo test --workspace --no-default-features
cargo test --workspace --all-features
cargo deny check
```

## Reference fixtures

Each crate's `fixtures/` directory holds the expected outputs, generated by signify-ts at the
commit pinned in `tools/reference-vectors/package.json` and, for the capabilities signify-ts cannot
emit, by the keripy release pinned in `tools/reference-vectors/pyproject.toml`. Tests read them and
never need Node, Python or the network. Each fixture directory has a README with its provenance.

```bash
npm ci --prefix tools/reference-vectors
uv sync --locked --project tools/reference-vectors
npm run --prefix tools/reference-vectors check      # regenerate and fail if anything changed
npm run --prefix tools/reference-vectors generate   # regenerate after an intended change
```

## System tests

`signify-keria-systest` talks to a real KERIA. Its tests are `#[ignore]`d and behind the `live`
feature, and they run only with `SIGNIFY_KERIA_ADMIN_URL` and `SIGNIFY_KERIA_BOOT_URL` set. Setting
`SIGNIFY_RECORD=1` rewrites the recorded observations under
`crates/signify-client/fixtures/keria-integration/observations/`.

## Fuzzing

```bash
cargo +nightly fuzz list
cargo +nightly fuzz run client_lifecycle
```
