# Changelog

> Following [Keep a Changelog](https://keepachangelog.com/en/1.1.0/)
> and [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

The three crates in this workspace, `signify-client`, `signify-http` and `signify-keys`, are
released together and share a version.

## [0.1.0] - 2026-10-22

First release.

### Added

- `signify-keys`: key creation, storage, rotation and signing for the identifiers one controller
  manages; identifier habitats; the client controller derived from a passcode and the KERIA agent
  it delegates to; ACDC issuance, revocation and IPEX messages signed with a keeper.
- `signify-http`: the `Transport` trait with a scripted transport for tests and, behind the
  `http-client` feature, a production transport on hyper, rustls and tokio; typed requests and
  responses; HTTP message signatures on keri-http-auth; retries with a pluggable clock.
- `signify-client`: the client lifecycle (boot, state, connect, signed fetch); every KERIA
  endpoint family; waiting on long-running operations; multisig inception and group operations;
  IPEX credential presentation; passcode rotation. Re-exports the crates it is built on so an
  application depends on `signify-client` alone.
- Cross-language fixtures generated by [signify-ts] and, where signify-ts cannot emit them, by
  [keripy], with both pinned through npm and uv.

[signify-ts]: https://github.com/WebOfTrust/signify-ts
[keripy]: https://github.com/WebOfTrust/keripy
